v0.3.1 是 v0.3.0 之后的 patch 版本：公开 API 只有新增，没有删除或改签名，升级不需要改调用点。本版给代码编辑器补上折叠、空白与行尾标记、横向滚动偏移和折行偏移，让高亮拿到逻辑行号，新增可拖拽排序的宫格，让 `text.Editor` 在输入法组字时给出已上屏的文字，并修掉 Windows 最小化后的窗口预览、macOS 15 SDK 的缩放光标与单选的浮层宽度。macOS 是参考平台。

v0.3.1 is a patch release after v0.3.0: the public API only gains members, with no removal or signature change, so upgrading needs no call-site edits. It adds line folding, whitespace and end-of-line markers, sideways scroll offsets and soft-wrap offsets to the code editor, gives highlighters the logical line index, adds a reorder grid draggable by the caller, has `text.Editor` report the committed text during an input-method composition, and fixes the Windows window preview after minimize, the macOS 15 SDK resize cursors and the width of a select's popup. macOS is the reference platform.

## 拿到它 · Getting it

`go get github.com/vivaui/viva@v0.3.1`，需要 Go 1.26 或更新；系统依赖与 v0.3.0 相同，只有显示系统网页的应用需要对应的网页组件，只有选用 GTK 外壳（`-tags vivagtk`）的应用需要系统的 GTK 3。每个 Release 附带 `viva` 命令的预编译压缩包、`SHA256SUMS`，以及 Homebrew 与 Scoop 清单（`brew install vivaui/tap/viva`，或 `scoop bucket add vivaui https://github.com/vivaui/homebrew-tap` 后 `scoop install viva`）；压缩包没有代码签名或公证，浏览器下载的 macOS 版会被 Gatekeeper 拦下，brew、curl 与 `go install` 不受影响。

`go get github.com/vivaui/viva@v0.3.1` needs Go 1.26 or newer; the system requirements are those of v0.3.0, and only an application that shows web pages needs the matching web component and only one that opts into the GTK shell (`-tags vivagtk`) needs the system's GTK 3. Every Release carries prebuilt archives of the `viva` command, `SHA256SUMS`, and Homebrew and Scoop manifests (`brew install vivaui/tap/viva`, or `scoop bucket add vivaui https://github.com/vivaui/homebrew-tap` then `scoop install viva`); the archives are not code-signed or notarized, so a browser download on macOS is stopped by Gatekeeper while brew, curl and `go install` are not affected.

## 有什么 · What is in it

- 新增 `components.CodeEditorFoldRange` 与 `CodeEditorFoldMarker`，按行折叠代码，并在行号栏之前给出可见行的折叠按钮
- 新增 `CodeEditor` 的空白与行尾标记，空格、制表符和硬换行各自可辨，并且不改变排版几何
- 新增 `CodeEditor.SoftWrapOffsets`，一次折叠布局即可取回可见的折行偏移，调用方不必自己再排一遍
- 新增 `CodeEditor.ScrollX`、`SetScrollX`与 `MaxScrollX`，横向滚动可以读写并夹在内容宽度之内
- `CodeEditor` 的高亮回调改为 `HighlightLine`，带上逻辑行号，滚动与折行之后仍然对得上源码行
- 新增 `components.ReorderGridState`，调用方自行放置的条目可以按住拖动重排，落点与当前位置都有查询
- 新增 `text.Editor.CommittedString`，输入法组字期间给出已经上屏的文字，未组字时不分配
- 新增 `components.HierarchyMenuState` 与 `PaintHierarchyMenu`，把单选的浮层树列表独立出来，任何控件都能挂一个；`SingleSelect` 的行为不变
- 新增 `SingleSelectState.Separator`，按分隔符把取值切成路径，弹出列表逐级展开，悬停即开、左右键换层、Escape 先退一层，选择父级则选中到它为止
- `headless` 收到不含文字的粘贴事件时也交给终端，图片这类剪贴板内容因此能到达应用
- 修复 Windows 最小化后任务栏预览显示旧画面被拉伸的一角，现在保留最后一帧可见画面直到还原重绘
- 修复在 SDK 15 以下编译时 macOS 15 的缩放光标不可用
- 修复单选弹出层与输入框等宽，共享长前缀的路径被截断成看起来相同的行

- New `components.CodeEditorFoldRange` and `CodeEditorFoldMarker` fold lines of code and give visible rows a fold button in a lane before the line numbers
- New whitespace and end-of-line markers on `CodeEditor`: a space, a tab and a hard wrap are each visible, and the layout geometry does not change
- New `CodeEditor.SoftWrapOffsets` returns the visible wrap offsets from the folded layout in one pass, so the caller does not lay the text out again
- New `CodeEditor.ScrollX`, `SetScrollX` and `MaxScrollX`, so sideways scrolling can be read, written and clamped to the content width
- The `CodeEditor` highlight callback is now `HighlightLine`, with the logical line index, which still names the source line after scrolling and folding
- New `components.ReorderGridState`, where items the caller positions can be dragged into a new order, with both the target and the current position available
- New `text.Editor.CommittedString`, the text already committed during an input-method composition, allocating nothing while none is in progress
- New `components.HierarchyMenuState` and `PaintHierarchyMenu` extract the select's fly-out tree list, so any control can anchor one; `SingleSelect` behaves as before
- New `SingleSelectState.Separator` splits values into paths and opens the popup one level at a time: a fly-out opens on hover, Left and Right move between levels, Escape closes one level first, and choosing a parent selects up to it
- `headless` delivers a paste with no text to a terminal, so clipboard content such as an image reaches the application
- Fixed the Windows taskbar preview showing a stretched corner of the old frame after a window is minimized, by keeping the last visible frame until the restore paints
- Fixed the macOS 15 resize cursors being unavailable when building against an older SDK
- Fixed a select's popup being exactly as wide as its field, which ellipsized paths that share a long prefix into rows that look the same

## 证据在哪 · Where the evidence is

折叠、空白标记与折行偏移都带测试：折叠后的行缓存与行号在滚动后仍对得上源码偏移，折叠布局只统计可见行，稳态绘制不额外分配；空白与行尾标记不改变几何，横向滚动时按可见列裁剪；`SoftWrapOffsets` 复用同一份折行布局并复用缓冲。零分配断言只在非 `-race` 下生效，与仓库既有做法一致。

Folding, whitespace markers and wrap offsets each carry tests: a folded row cache and its line numbers still match source offsets after scrolling, the folded layout counts only visible rows, and steady painting allocates nothing extra; the whitespace and end-of-line markers leave geometry unchanged and clip to the visible columns while scrolled sideways; `SoftWrapOffsets` reuses one wrapped layout and one buffer. The zero-allocation assertions hold only without `-race`, as elsewhere in the repository.

## 注意 · Caveats

`SingleSelectState.Wheel` 的方法体从单行改写为多行，签名与行为不变。区间内公开包（`app`、`ui`、`text`、`flex`、`headless`、`markdown`、`components`）只有新增成员，`components` 没有删除或改签名。

`SingleSelectState.Wheel` was rewritten from one line into several, with the same signature and behaviour. The public packages in this interval (`app`, `ui`, `text`, `flex`, `headless`, `markdown`, `components`) only gain members, and `components` neither removes nor changes a signature.
