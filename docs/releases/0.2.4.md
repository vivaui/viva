v0.2.4 是 v0.2.3 之后的 patch 版本：公开 API 只有新增，没有删除或改签名，升级不需要改调用点。本版带来窗口之外的拖动预览、在文件管理器里定位文件、用指定程序打开文件、界面字体家族与原生全屏，并修掉 Windows 恢复窗口位置、多行长文本、macOS 输入法与快捷键、Linux 修饰键、交换链与桌面设置监听等一批问题。macOS 是参考平台。

v0.2.4 is a patch release after v0.2.3: the public API only gains members, with no removal or signature change, so upgrading needs no call-site edits. It brings a drag preview that follows the pointer out of the window, revealing a file in the system file manager, opening a file with a chosen program, an interface font family and native fullscreen, and fixes a batch of problems with restored window positions on Windows, long multi-line text, input methods and shortcuts on macOS, and modifiers, swapchains and desktop settings on Linux. macOS is the reference platform.

## 拿到它 · Getting it

`go get github.com/vivaui/viva@v0.2.4`，需要 Go 1.26 或更新；系统依赖与 v0.2.3 相同，只有显示系统网页的应用需要对应的网页组件，只有选用 GTK 外壳（`-tags vivagtk`）的应用需要系统的 GTK 3。每个 Release 附带 `viva` 命令的预编译压缩包、`SHA256SUMS`，以及 Homebrew 与 Scoop 清单（`brew install vivaui/tap/viva`，或 `scoop bucket add vivaui https://github.com/vivaui/homebrew-tap` 后 `scoop install viva`）；压缩包没有代码签名或公证，浏览器下载的 macOS 版会被 Gatekeeper 拦下，brew、curl 与 `go install` 不受影响。

`go get github.com/vivaui/viva@v0.2.4` needs Go 1.26 or newer; the system requirements are those of v0.2.3, and only an application that shows web pages needs the matching web component and only one that opts into the GTK shell (`-tags vivagtk`) needs the system's GTK 3. Every Release carries prebuilt archives of the `viva` command, `SHA256SUMS`, and Homebrew and Scoop manifests (`brew install vivaui/tap/viva`, or `scoop bucket add vivaui https://github.com/vivaui/homebrew-tap` then `scoop install viva`); the archives are not code-signed or notarized, so a browser download on macOS is stopped by Gatekeeper while brew, curl and `go install` are not affected.

## 注意 · Caveats

没有公开 API 被删除或改签名（用 `apidiff` 对比 v0.2.3 的公开包，只有新增），升级不需要改调用点；按 1.0 之前的语义新增 API 通常进 minor，这次与 v0.2.2、v0.2.3 一样按 patch 发布，是因为没有破坏性变更。有六处行为变化值得知道：

- `OnShortcut` 现在也收到不带修饰键的可打印按键，返回 `true` 才会拦下，不处理时照常进入原生输入
- 多行文本框里 Control+Enter 与 Meta+Enter 先交给 `OnShortcut`，应用不处理才换行
- macOS 菜单栏现在自带隐藏、隐藏其他、最小化、缩放与「全部置于前面」，应用自己再添加会重复
- `app.MonospaceFamilies` 在 macOS 上按实际步进宽度判定等宽，会列出以前没有的家族
- Linux 上自定义标题栏的窗口按钮在 GNOME/Adwaita 与 KDE/Breeze 上从方形变成圆形
- 菜单、命令列表与组合框按调用方标记的当前行绘制，`CommandItem.Selected` 与 `ComboboxItem.Highlighted` 决定点亮哪一行，指针焦点不再直接点亮

No public API is removed and no signature changes (comparing the public packages with v0.2.3 using `apidiff` shows additions only), so upgrading needs no call-site edits; by pre-1.0 semantics new API usually lands in a minor release, and like v0.2.2 and v0.2.3 this ships as a patch because nothing breaks. Six behaviors are worth knowing:

- `OnShortcut` now also receives printable keys without modifiers, and only a `true` return keeps them from reaching native input
- In a multi-line field Control+Enter and Meta+Enter go to `OnShortcut` first, and a chord the application leaves still breaks the line
- The macOS menu bar now carries Hide, Hide Others, Minimize, Zoom and Bring All to Front, so an application that adds its own would duplicate them
- `app.MonospaceFamilies` judges monospace by measured advance on macOS and lists families it did not list before
- Window buttons of a custom titlebar turn from rectangles into circles on GNOME/Adwaita and KDE/Breeze on Linux
- Menus, command lists and comboboxes paint the current row the caller marks, with `CommandItem.Selected` and `ComboboxItem.Highlighted` choosing it rather than pointer focus
