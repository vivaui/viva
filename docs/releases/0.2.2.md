v0.2.2 是 v0.2.1 之后的 patch 版本：公开 API 只有新增，没有删除或改签名，升级不需要改调用点。本版带来系统网页宿主、自定义 URL scheme、浏览器里的 `app.RunCanvas`、双栏代码对比和 Linux 的可选 GTK 3 外壳，并修掉 macOS 关窗崩溃、Windows 输入框选区与输入法下划线、Linux 输入框缺少鼠标选择等问题。macOS 是参考平台。

v0.2.2 is a patch release after v0.2.1: the public API only gains members, with no removal or signature change, so upgrading needs no call-site edits. It brings a host for pages of the system's web engine, custom URL schemes, `app.RunCanvas` in the browser, a two-pane code diff and an opt-in GTK 3 shell for Linux, and fixes a crash after a macOS window closes, Windows text-field selection and input-method underlines, and Linux text fields that lacked pointer selection. macOS is the reference platform.

## 拿到它 · Getting it

`go get github.com/vivaui/viva@v0.2.2`，需要 Go 1.26 或更新；系统依赖与 v0.2.1 相同，只有显示系统网页的应用需要对应的网页组件，只有选用 GTK 外壳（`-tags vivagtk`）的应用需要系统的 GTK 3。每个 Release 附带 `viva` 命令的预编译压缩包、`SHA256SUMS`，以及 Homebrew 与 Scoop 清单（`brew install vivaui/tap/viva`，或 `scoop bucket add vivaui https://github.com/vivaui/homebrew-tap` 后 `scoop install viva`）；压缩包没有代码签名或公证，浏览器下载的 macOS 版会被 Gatekeeper 拦下，brew、curl 与 `go install` 不受影响。

`go get github.com/vivaui/viva@v0.2.2` needs Go 1.26 or newer; the system requirements are those of v0.2.1, and only an application that shows web pages needs the matching web component and only one that opts into the GTK shell (`-tags vivagtk`) needs the system's GTK 3. Every Release carries prebuilt archives of the `viva` command, `SHA256SUMS`, and Homebrew and Scoop manifests (`brew install vivaui/tap/viva`, or `scoop bucket add vivaui https://github.com/vivaui/homebrew-tap` then `scoop install viva`); the archives are not code-signed or notarized, so a browser download on macOS is stopped by Gatekeeper while brew, curl and `go install` are not affected.

## 注意 · Caveats

没有公开 API 被删除或改签名（用 `apidiff` 对比 v0.2.1 的公开包，只有新增），升级不需要改调用点；按 1.0 之前的语义新增 API 通常进 minor，这次与 v0.2.1 一样按 patch 发布，是因为没有破坏性变更。有三处行为变化值得知道：

- 内置的 `DarkTheme` 与 `LightTheme` 现在带独立的 `Selection` 与 `SelectionForeground`，`Input` 与 `Textarea` 的选区默认改用它们而不是 `Primary`；自定义主题不设置时仍回退到 `Primary`
- Linux 原生文本框现在优先处理 Ctrl+A、Home、End 与按词移动，应用对这些组合键的绑定在文本框获得焦点时收不到
- `ScrollArea` 默认几何不变，只有调用 `ReserveScrollbars` 才让出滚动条的位置

No public API is removed and no signature changes (comparing the public packages with v0.2.1 using `apidiff` shows additions only), so upgrading needs no call-site edits; by pre-1.0 semantics new API usually lands in a minor release, and like v0.2.1 this ships as a patch because nothing breaks. Three behaviors are worth knowing:

- The built-in `DarkTheme` and `LightTheme` now carry their own `Selection` and `SelectionForeground`, and `Input` and `Textarea` use them for the selection instead of `Primary`; a custom theme that leaves them unset still falls back to `Primary`
- Linux native text fields now handle Ctrl+A, Home, End and word moves themselves, so an application's binding for one of them is not received while a text field has focus
- The default geometry of `ScrollArea` is unchanged; only a scroll area that calls `ReserveScrollbars` gives its scrollbar strips up from the viewport
