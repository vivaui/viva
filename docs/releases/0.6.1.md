v0.6.1 是 v0.6.0 之后的 patch 版本：修复窗口输入时序、绘制顺序、文本缓存与 Linux 状态区的一批问题，并新增若干可选 API（Markdown 图片、异步 web 响应头、可扩展表格行、区域语言排序等），已有 API 不变，升级不需要改调用点。macOS 是参考平台。

v0.6.1 is a patch release after v0.6.0: it fixes a set of window input, paint order, text cache and Linux status-area problems and adds a number of opt-in APIs (Markdown images, asynchronous web response headers, expandable table rows, locale-aware collation and more). Existing APIs are unchanged, so upgrading needs no call-site edits. macOS is the reference platform.

## 拿到它 · Getting it

`go get github.com/vivaui/viva@v0.6.1`，需要 Go 1.26 或更新；系统依赖与 v0.6.0 相同。每个 Release 附带 `viva` 命令的预编译压缩包、`SHA256SUMS`，以及 Homebrew 与 Scoop 清单（`brew install vivaui/tap/viva`，或 `scoop bucket add vivaui https://github.com/vivaui/homebrew-tap` 后 `scoop install viva`）；压缩包没有代码签名或公证，浏览器下载的 macOS 版会被 Gatekeeper 拦下，brew、curl 与 `go install` 不受影响。

`go get github.com/vivaui/viva@v0.6.1` needs Go 1.26 or newer; the system requirements are those of v0.6.0. Every Release carries prebuilt archives of the `viva` command, `SHA256SUMS`, and Homebrew and Scoop manifests (`brew install vivaui/tap/viva`, or `scoop bucket add vivaui https://github.com/vivaui/homebrew-tap` then `scoop install viva`); the archives are not code-signed or notarized, so a browser download on macOS is stopped by Gatekeeper while brew, curl and `go install` are not affected.

## 有什么 · What is in it

- 过渡动画进行时 Windows 不再推迟窗口鼠标输入：新增 `platform.Config.FramePresented`，在每次呈现后申请下一帧，Windows 重新通过 `WM_PAINT` 绘制，点击侧栏或设置分类不再等图标动画结束
- 文本与图片按调用顺序绘制：每个绘制原语带单调的绘制序号，GPU 实例布局与原生矩形 ABI 不变
- 修复反复扫描时成型行缓存的抖动：改为有界的新近度与频率准入，保留原有行预算，只在溢出时启用准入记录
- 修复原生输入法取消组合时破坏编辑历史的问题
- 同一行混排文字在测量与绘制时共用一个基线
- Windows 向旧式终端转发可打印的 Alt 组合键
- Windows 复用原生文本图片：按内容键保留不可变标签图片并限制空闲缓存，33 个标签的页面切换从 16.6-19.8 ms 降到 4.6-4.7 ms
- macOS 在 Metal 设备或资源丢失后重建设备、队列、管线与标签纹理，连续丢失时停止窗口而不是空转
- macOS 矩形实例缓冲按场景大小增长并就地写入，不再每帧按 1.25 倍复利扩容
- Linux 状态项注册不再阻塞事件循环，host 的延迟应答不会让图标被丢弃；注册期间的菜单布局与标签请求也得到保护
- Windows 在 Explorer 重启后隐藏通知载体，不再留下失效图标
- `Box.Shortcut` 的矩形包含 Tree 的行，`Box.LabelFor` 让一行中的某一部分为整行提供标签，无字标签下的控件也保留名字
- `ScrollState.Follow` 让手势在两次绘制之间停止列表跟随，`Box.Follow` 改为转调它；`ScrollState.Dragging()` 让应用自绘的行在拖动滚动条时不进入高亮
- 列表在应用请求的滚动位置的那次绘制中显示该位置，跟随中的列表把行放在固定的那一端
- Windows 与 Linux 的小图标按标记裁切并铺满单元格，次级图标保留边距；应用仍然只嵌入一张图片
- `MarkdownStyle.Image` 让 `MarkdownView` 从宿主位图绘制图片，新增只读的 `CodeRepresentation`，`CodeEditorMarkLayer` 让代码编辑器的标记层可以各自着色
- `PopoverOptions` 新增 `Headerless`、`Padding` 与 `Instant`，菜单式弹出层可以没有标题行、使用菜单内边距并立即出现；零值保持原有行为
- `Editor.TrackEdits` 与 `Editor.EditsSince` 提供有界的原语编辑流，供范围跟踪在编辑后仍能定位
- 新增 `gfx` 任意四边形绘制与带边界变换文字，powerline 与旧式计算字形按单元格几何绘制
- 新增 `text/collation` 子包：按语言排序用户可见名称，简体中文用拼音、繁体中文用笔画、其余用 CLDR 顺序；不导入的应用不链接 CLDR 表
- `MenuItems.Beside()` 在锚点旁打开菜单，`Config.OnActivate` 报告顶层窗口激活，系统打开的文档通过 `Application.OnOpenFile` 交给应用
- 自定义 web scheme 可以异步返回响应头
- 组合框显示次级详情，并保留原生查询编辑
- 页面通过 `PageConfig.ScrollbarSize` 统一滚动条厚度，表格与滚动区域自己绘制悬停滚动条并在拖动时让出行
- `TableColumn.EndInset` 与 `Table.Detail` 支持可展开的表格行，在不改变选择与几何的前提下显示多行详情
- Linux 在没有可用 Vulkan 设备时用 CPU 光栅器绘制窗口，帧边距在 CPU 路径合成，CPU 文字按桌面设置做 LCD 次像素抗锯齿；`VIVA_SOFTWARE_RENDERING=1` 可强制 CPU
- Windows 安装包拒绝在 Windows 10 以下安装并给出说明，安装包与 zip 可通过重复的 `--file SRC=DEST` 携带原生运行时文件
- `app/singleinstance` 的占用目录改为平台每用户位置，不同 `TMPDIR` 或会话启动的副本不再各自占主
- 框选与命中文本改用 `Canvas.HitText`，把文本字段几何移出 `gfx.Hit`；帧按呈现节拍驱动，指针与滚轮重绘合并到该节拍
- 重新生成 scroll-area、table、markdown 与 popover 的组件安装模板，组件生成器的检查恢复通过

- While a transition runs, Windows no longer defers the window's mouse input: the new `platform.Config.FramePresented` hook arms the next frame after each present, and Windows paints through `WM_PAINT` again, so a click on the sidebar or a settings category no longer waits for the icon motion
- Text and images paint in the order they are called: every primitive carries a monotonic paint order, with the GPU instance layout and native rectangle ABI unchanged
- Repeated scans no longer thrash the shaped-line cache: bounded recency and frequency admission replace whole-generation eviction, keeping the existing line budgets and tracking admission only on overflow
- Cancelling native composition no longer corrupts the edit history
- Mixed text in one row is measured and painted on a shared baseline
- Windows delivers printable Alt chords to legacy terminals again
- Windows reuses native text pictures by typed content key with a bounded idle cache, cutting a 33-label page switch from 16.6-19.8 ms to 4.6-4.7 ms
- macOS rebuilds its device, queue, pipelines and label textures after a Metal loss, and stops the window rather than spinning when losses keep arriving
- The macOS rectangle instance buffer grows with the scene and is written in place instead of compounding by a quarter every frame
- Linux registers status items without blocking the event loop, so a host's delayed answer no longer drops the icon; menu layout and label requests during registration are guarded too
- Windows hides the notification carrier across Explorer restarts instead of leaving a dead icon
- `Box.Shortcut` includes a Tree's rows, `Box.LabelFor` lets a part of a row label the row, and a control keeps its name under a wordless label
- `ScrollState.Follow` stops a List following between paints and `Box.Follow` now delegates to it; `ScrollState.Dragging()` keeps application-painted rows from taking hover while a bar is dragged
- A List shows its requested scroll in the paint that applies it, and a following List places its rows at the end it is pinned to
- Windows and Linux small icons crop to the mark and fill the cell, with secondary icons keeping their margin; the application still embeds one image
- `MarkdownStyle.Image` lets `MarkdownView` draw images from host bitmaps, a display-only `CodeRepresentation` is new, and `CodeEditorMarkLayer` lets code editor mark layers carry their own colors
- `PopoverOptions` gains `Headerless`, `Padding` and `Instant`, so a menu-like popover can omit its title row, use the menus' inset and appear immediately; the zero values leave every existing popover unchanged
- `Editor.TrackEdits` and `Editor.EditsSince` provide an opt-in bounded primitive-edit stream that keeps range tracking valid across an edit
- `gfx` draws arbitrary quads with bounded transformed text, and draws powerline and legacy computing glyphs as cell geometry
- The new `text/collation` subpackage orders user-visible names by language: pinyin for Simplified Chinese, stroke count for Traditional Chinese and CLDR order otherwise; an application that does not import it links no CLDR tables
- `MenuItems.Beside()` opens a menu beside its anchor, `Config.OnActivate` reports top-level window activation, and documents the system opens arrive through `Application.OnOpenFile`
- A custom web scheme can answer with headers asynchronously
- A combobox shows secondary details while keeping native query editing
- `PageConfig.ScrollbarSize` sets a page's bar thickness, and tables and scroll areas own their hover bars and yield during a drag
- `TableColumn.EndInset` and `Table.Detail` support expandable table rows that show multi-line detail without changing selection or geometry
- Linux draws windows with the CPU rasterizer when no usable Vulkan device exists, composes the frame margin on the CPU path and blends CPU text with the desktop's LCD setting; `VIVA_SOFTWARE_RENDERING=1` forces the CPU
- The Windows installer refuses to install below Windows 10 and explains why, and installers and zips can carry native runtime files through repeatable `--file SRC=DEST` flags
- `app/singleinstance` claims in the platform's per-user location, so copies started with different `TMPDIR` values or sessions no longer both become primary
- Hit text moves to `Canvas.HitText`, text-field geometry leaves `gfx.Hit`, and frames are paced by presentation with pointer and wheel repaints coalesced onto that frame
- The scroll-area, table, markdown and popover component installation templates are regenerated, so the component generator checks pass again

## 证据在哪 · Where the evidence is

- 发布门禁在 macOS、Linux 与 Windows 的矩阵上运行 `go vet`、`go test ./... -count=1` 与 `-tags vivahead` 的无头构建；组件安装模板检查由 `cmd/viva` 的 `TestGeneratedRecipesAreCurrent` 与 `TestInstalledRecipesMatchReferenceSource` 覆盖
- Windows 11 真机（2880x1800、200%）测得 33 个标签的页面切换从 16.6-19.8 ms 降到 4.6-4.7 ms，像素逐标签比对不变；原生文本图片复用、滚动条与设置导航在该机验证
- Linux X11 真机跑通 CPU 渲染路径与带边框窗口的回读测试；CPU 与 GPU 离屏渲染同一标签的差异不超过每通道一级
- 体积报告 `docs/benchmarks/2026-11-12-size-attribution-darwin-arm64.md` 记录了 `hello darwin/arm64` 的构成与增长来源

- The release gate runs `go vet`, `go test ./... -count=1` and the `-tags vivahead` headless build across the macOS, Linux and Windows matrices; `TestGeneratedRecipesAreCurrent` and `TestInstalledRecipesMatchReferenceSource` in `cmd/viva` cover the component installation templates
- A real Windows 11 machine (2880x1800, 200%) measured a 33-label page switch dropping from 16.6-19.8 ms to 4.6-4.7 ms with pixels compared label by label; native text-picture reuse, scrollbars and settings navigation were verified there
- Real X11 verified the CPU rendering path and the framed-window read-back; CPU and GPU offscreen renders of the same label differ by at most one level per channel
- The size report `docs/benchmarks/2026-11-12-size-attribution-darwin-arm64.md` records what `hello darwin/arm64` carries and where its growth came from

## 注意 · Caveats

- 本版使用 patch 版本号，但包含新增 API；没有删除或改变已有导出 API，升级不需要迁移
- `hello` 的尺寸仍高于 `benchmarks/size.sh` 的告警上限；尺寸 job 保持非阻塞，等布局/控件边界决策后再恢复硬限制

- This release uses a patch version number but adds APIs; no existing exported API is removed or changed, so no migration is needed
- `hello` remains above the alarm limit in `benchmarks/size.sh`; the size job stays non-blocking until the layout/widget boundary decision restores a hard limit
