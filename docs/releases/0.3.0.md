v0.3.0 是 v0.2.4 之后的 minor 版本：公开 API 大量新增，`components` 包也移除了几个成员，所以按 1.0 之前的语义进 minor 而不是 patch，迁移方式写在文末。本版把代码编辑器与 Markdown 重建成字符网格，带来随包字体注册、剪贴板里的文件、带签名的应用更新、结构化诊断、图标动效与悬停预览、修饰键单独按下的通知，并修掉后台窗口空转重绘、Windows 更新与内存、终端图标墨迹被裁掉一批问题。macOS 是参考平台。

v0.3.0 is a minor release after v0.2.4: the public API gains a great deal, and the `components` package also loses a few members, so by pre-1.0 semantics this is a minor rather than a patch and the migration is at the end of these notes. The code editor and Markdown are rebuilt on a character grid, and the release brings per-process font registration, the files the clipboard holds, signed application updates, structured diagnostics, icon motion and hover previews, and notice of a modifier key pressed and released on its own, along with fixes for a background window painting nothing anyone can see, Windows updating and memory, and terminal icon ink being cut at its cell. macOS is the reference platform.

## 拿到它 · Getting it

`go get github.com/vivaui/viva@v0.3.0`，需要 Go 1.26 或更新；系统依赖与 v0.2.4 相同，只有显示系统网页的应用需要对应的网页组件，只有选用 GTK 外壳（`-tags vivagtk`）的应用需要系统的 GTK 3。每个 Release 附带 `viva` 命令的预编译压缩包、`SHA256SUMS`，以及 Homebrew 与 Scoop 清单（`brew install vivaui/tap/viva`，或 `scoop bucket add vivaui https://github.com/vivaui/homebrew-tap` 后 `scoop install viva`）；压缩包没有代码签名或公证，浏览器下载的 macOS 版会被 Gatekeeper 拦下，brew、curl 与 `go install` 不受影响。

`go get github.com/vivaui/viva@v0.3.0` needs Go 1.26 or newer; the system requirements are those of v0.2.4, and only an application that shows web pages needs the matching web component and only one that opts into the GTK shell (`-tags vivagtk`) needs the system's GTK 3. Every Release carries prebuilt archives of the `viva` command, `SHA256SUMS`, and Homebrew and Scoop manifests (`brew install vivaui/tap/viva`, or `scoop bucket add vivaui https://github.com/vivaui/homebrew-tap` then `scoop install viva`); the archives are not code-signed or notarized, so a browser download on macOS is stopped by Gatekeeper while brew, curl and `go install` are not affected.

## 有什么 · What is in it

- 新增 `app.RegisterFont`，把应用自带的 .ttf、.otf 或 .ttc 注册进本进程而不装进用户的字体库，返回可交给 `ui.MonoFamily` 与 `SetInterfaceFontFamily` 的家族名
- 新增 `app.ClipboardFiles` 与 `ErrNoFiles`，读取文件管理器放进剪贴板的文件绝对路径，macOS、Windows 与 Linux 已实现
- 新增 `app.Application.SetProgress`，把工作进度画在应用图标上
- 新增 `app.WebViewConfig.Proxy`，让网页只经由本机回环地址上的 SOCKS5 代理访问网络，Windows 与 Linux 已实现
- 新增 `update` 包与 `viva feed` 命令，`update.Check`、`Client.Download` 与 `update.Install` 完成校验签名、下载与安装，`viva feed` 生成签名的更新源

- 新增 `flex.BindIconHover` 与 `components.IconHover`，指针驻留后播放一次图标变换，驻留时间与时长由调用方给定

- 新增 `text.CellWidth` 与 `text.Editor` 的代码编辑操作：自动缩进、Tab 与 Shift+Tab、行注释开关、行移动/复制/删除、括号与引号配对、智能退格与 Home，以及 `ByteOffset` 与 `RuneIndex`
- `components.CodeEditor` 改为字符网格布局，自带行号、当前行底色、括号匹配、查找标记、折行或横向滚动与两侧滚动条，宽字符占两格、Tab 到制表位
- 新增 `components.CodeEditorGutterMarker` 与 `CodeEditorSnapshot.GutterMarkers`，在行号之前或单独一栏画断点、诊断等标记
- 新增 `MarkdownView.Anchors`、`YAtSource` 与 `SourceAtY`，把排版后的每一块与其源码字节范围和纵向位置对应起来
- `CodeEditor` 新增 `ScrollY`、`SetScrollY`、`MaxScrollY`、`YAtOffset` 与 `OffsetAtY`，源码编辑器与其 Markdown 预览可以停在同样的内容上

- macOS、Windows 与 Linux 的比例文字改用原生斜体字形绘制，不再是合成的斜切
- 后台唤醒对齐到显示器的帧网格，持续 `Invalidate` 的终端不再以高于刷新率的频率重绘

- New `app.RegisterFont` makes a .ttf, .otf or .ttc the application carries available to this process without installing it, and returns the family for `ui.MonoFamily` and `SetInterfaceFontFamily`
- New `app.ClipboardFiles` and `ErrNoFiles` read the absolute paths of the files a file manager put on the clipboard, implemented on macOS, Windows and Linux
- New `app.Application.SetProgress` paints work progress on the application icon
- New `app.WebViewConfig.Proxy` holds a web view to a SOCKS5 proxy on this machine, so a page reaches only what the proxy reaches, implemented on Windows and Linux
- New `update` package and `viva feed` command: `update.Check`, `Client.Download` and `update.Install` verify the signature, download and install, and `viva feed` writes the signed feed
- New `diagnostics` package: a structured diagnostic stream with level, subsystem, code and attributes, with slog adapters
- New `app.Config.OnModifierTap` and `ui.ModifierTapEvent` report a modifier key pressed and released on its own, which an application builds gestures such as a double Shift on
- New `ui.PointerCancel` replaces the exit event when the platform takes a press for itself, as a custom titlebar starting a window move does
- New `app/iconpng.DecodeFit` shrinks an icon master while decoding, so an application that embeds a 1024 px master keeps no megabytes of pixels for its life
- New `ui.Motion`, `ui.Curve`, `ui.CubicBezier`, `ui.Spring` and `ui.Lerp`, one set of easing and spring curves for animation
- New `flex.BindIconHover` and `components.IconHover` play an icon transform once the pointer dwells, with the dwell and the duration the caller's

- New text selection and copy on `components.Table`: `TableSelection` is the range, `SelectedText` the text, and `UseSelectionState` reuses the per-paint buffers
- New `components.PaintFindBar` and `components.PaintGoToLine`, two stateless bars, with plain and regular-expression search, whole word, replace-all and a `Session` that drives the find bar in `text/find`
- New `text.CellWidth` and the code operations of `text.Editor`: auto-indent, Tab and Shift+Tab, line comment toggle, line move, duplicate and delete, paired brackets and quotes, smart Backspace and Home, plus `ByteOffset` and `RuneIndex`
- `components.CodeEditor` is laid out on a character grid, with line numbers, the current-line tint, bracket matching, find marks, soft wrap or sideways scrolling, and both scrollbars, with wide characters on two cells and tabs run to the stop
- New `components.CodeEditorGutterMarker` and `CodeEditorSnapshot.GutterMarkers` paint breakpoints or diagnostics in a lane before the line numbers or on their own
- New `MarkdownView.Anchors`, `YAtSource` and `SourceAtY` tie each laid-out block to the byte range it came from and the vertical position it took
- `CodeEditor` gains `ScrollY`, `SetScrollY`, `MaxScrollY`, `YAtOffset` and `OffsetAtY`, so a source editor and its Markdown preview stay on the same content
- New `MarkdownView.CaretAt` gives the caret's rectangle at an offset in a laid-out Markdown view
- Proportional text on macOS, Windows and Linux is drawn with native italic faces rather than a synthesized slant

- Fixed the bundle inside a packaged zip carrying no notarization ticket, which made an offline machine refuse the update
- Fixed the macOS status item's menu detaching from the status item after its first showing
- Fixed Windows trusting a font's own fixed-pitch bit and leaving out families that are monospaced in fact
- Fixed Windows native text editors dropping a declared font weight
- Fixed a drag ending when the pointer left the window while a press was held, which lost the pointer exactly where auto-scroll needed it
- Fixed an update feed being impossible to write without an expiry, now optional through `viva feed -valid-for`

## 证据在哪 · Where the evidence is

重绘调度与窗口可见性的改动在真实桌面上验证：`tools/conformance/run.sh linux` 与 `run.sh windows` 各十项全部 PASS，包括「持续 `Invalidate` 600 ms 只按帧唤醒」与「隐藏窗口收到 `OnWake` 但不绘制、现身后再补一帧」。Windows 的标签纹理改动实测私有工作集：Motty 本地终端灌入三万行后从 125–157 MB 降到 91–96 MB，最大化时从 168 MB 降到 100 MB。字体注册在同一条路径上不做时增量可忽略：剥离后的 `examples/guides/hello` 在 macOS 只大 448 字节、Windows 大 1 KB、Linux 不变。

The repaint scheduling and window visibility changes were verified on real desktops: `tools/conformance/run.sh linux` and `run.sh windows` pass all ten checks each, including one where 600 ms of constant `Invalidate` still costs about one wake per frame, and one where a hidden window runs `OnWake` without painting and paints the frame it missed once it shows again. The Windows label texture change was measured as private working set on a Motty local terminal: 125–157 MB down to 91–96 MB after a 30k-line flood, and 168 MB down to 100 MB maximized. Registering fonts costs almost nothing along the same path: a stripped `examples/guides/hello` is 448 bytes larger on macOS, 1 KB on Windows and unchanged on Linux.

## 注意 · Caveats

`components` 包移除了公开成员，这是本版按 minor 而不是 patch 发布的原因。`CodeEditor` 从 `Textarea` 底座改为字符网格，因此 `CodeEditor.Layout` 字段与 `CodeEditorSnapshot` 的 `TextareaSnapshot` 嵌入一起消失，嵌套带来的 `DisplayValue`、`HideEditorText`、`InsetTop`、`InsetBottom`、`InsetRight`、`Invalid`、`Layout`、`NativeEditing`、`NoWrap` 也不再从 `CodeEditorSnapshot` 上可达。迁移方式：控件自身的移动、指针定位与滚动改由 `CodeEditor` 的方法完成（`Move`、`OffsetAt`、`Reveal`、`ScrollBy`、`Scroll`、`ScrollY` 与 `SetScrollY`），原来写在嵌入字段上的显示与几何选项直接写在 `CodeEditorSnapshot` 上，`NoWrap` 换成反向的 `Wrap`。其余公开包（`app`、`ui`、`text`、`flex`、`headless`、`markdown`）只有新增，用 `apidiff` 对比 v0.2.4 实测无删除、无签名变更。

The `components` package removes public members, which is why this ships as a minor rather than a patch. `CodeEditor` is rebuilt on a character grid instead of the `Textarea` base, so the `CodeEditor.Layout` field and the `TextareaSnapshot` embedded in `CodeEditorSnapshot` are gone, and the promotion it provided for `DisplayValue`, `HideEditorText`, `InsetTop`, `InsetBottom`, `InsetRight`, `Invalid`, `Layout`, `NativeEditing` and `NoWrap` no longer reaches `CodeEditorSnapshot`. To migrate: the control's own movement, pointer placement and scrolling are now methods on `CodeEditor` (`Move`, `OffsetAt`, `Reveal`, `ScrollBy`, `Scroll`, `ScrollY` and `SetScrollY`), the display and geometry options that lived in the embedded field are written directly on `CodeEditorSnapshot`, and `NoWrap` becomes `Wrap` with the opposite sense. Every other public package (`app`, `ui`, `text`, `flex`, `headless`, `markdown`) only gains members: comparing v0.2.4 with `apidiff` shows no removals and no signature changes.

另有几处行为变化值得知道：

- 隐藏、最小化或被遮挡的窗口仍会收到 `OnWake`，但不再绘制与提交帧，靠持续 `Invalidate` 刷新画面的应用在窗口不可见时不再拿到绘制
- 按下期间指针离开窗口不再产生退出事件，`PointerCancel` 只用于平台自己拿走的那次按下
- 热重载的宿主与 worker 必须来自同一 Viva 版本，版本不同时互相拒绝而不是勉强通信
- `app.MonospaceFamilies` 在 Windows 上按实测步进判定等宽，会列出以前没有的家族
- `app.WebViewConfig.Proxy` 在 macOS 上返回 `ErrUnsupported`，而不是打开一个会直连的页面

A few behaviors are also worth knowing:

- A hidden, minimized or covered window still runs `OnWake` but paints and presents nothing, so an application that repaints by calling `Invalidate` continuously gets no paint while its window is not visible
- The pointer leaving the window during a press no longer produces an exit event, and `PointerCancel` is only for a press the platform takes for itself
- A hot reload host and worker must come from the same Viva version, and two versions refuse each other rather than communicate badly
- `app.MonospaceFamilies` judges monospace by measured advance on Windows and lists families it did not list before
- `app.WebViewConfig.Proxy` fails with `ErrUnsupported` on macOS rather than opening a page that would connect directly
