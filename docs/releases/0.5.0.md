v0.5.0 是 v0.4.0 之后的 minor 版本，公开 API 只有新增，没有删除或改签名，升级不需要改调用点。本版把浏览器（WebAssembly）列为正式发布目标，新增静态平台与能力模型、异步系统集成、`keymap` 包、目录监视、文件列表剪贴板、控件的无外观 Base 与绘制钩子、可复用的树键盘导航与跨文本选区，并让终端单元按字体自身的度量；同时修复只描边元素被填充、输入文字与光标行盒不一致、Linux/X11 缩放卡顿和公证票据重试。macOS 是参考平台。

v0.5.0 is a minor release after v0.4.0: the public API only gains members, with no removal or signature change, so upgrading needs no call-site edits. It makes the browser (WebAssembly) a release target, adds a static platform and capability model, asynchronous system integrations, a `keymap` package, directory watching, file-list clipboard support, lookless control bases with draw hooks, reusable tree keyboard navigation and cross-text selection, and measures terminal cells from the font's own metrics; it also fixes border-only elements being filled, input text and caret line boxes disagreeing, Linux/X11 resize stalls and notarization ticket retries. macOS is the reference platform.

## 拿到它 · Getting it

`go get github.com/vivaui/viva@v0.5.0`，需要 Go 1.26 或更新；系统依赖与 v0.4.0 相同，只有显示系统网页的应用需要对应的网页组件，只有选用 GTK 外壳（`-tags vivagtk`）的应用需要系统的 GTK 3。浏览器目标用 `viva build --target web` 生成，必须通过 HTTP 或 HTTPS 提供；剪贴板、通知、密钥存储与全屏这些异步能力需要安全上下文（HTTPS 或 localhost）。每个 Release 附带 `viva` 命令的预编译压缩包、`SHA256SUMS`，以及 Homebrew 与 Scoop 清单（`brew install vivaui/tap/viva`，或 `scoop bucket add vivaui https://github.com/vivaui/homebrew-tap` 后 `scoop install viva`）；压缩包没有代码签名或公证，浏览器下载的 macOS 版会被 Gatekeeper 拦下，brew、curl 与 `go install` 不受影响。

`go get github.com/vivaui/viva@v0.5.0` needs Go 1.26 or newer; the system requirements are those of v0.4.0, and only an application that shows web pages needs the matching web component and only one that opts into the GTK shell (`-tags vivagtk`) needs the system's GTK 3. The browser target is built with `viva build --target web` and must be served over HTTP or HTTPS; the asynchronous clipboard, notification, secret-store and fullscreen capabilities need a secure context (HTTPS or localhost). Every Release carries prebuilt archives of the `viva` command, `SHA256SUMS`, and Homebrew and Scoop manifests (`brew install vivaui/tap/viva`, or `scoop bucket add vivaui https://github.com/vivaui/homebrew-tap` then `scoop install viva`); the archives are not code-signed or notarized, so a browser download on macOS is stopped by Gatekeeper while brew, curl and `go install` are not affected.

## 有什么 · What is in it

- 新增 `app.Platform`、`app.CurrentPlatform`、`app.Capability`、`app.Capabilities`、`app.SystemCapabilities` 与 `app.Supports`，应用可以静态判断目标平台和可用集成
- 新增 `ClipboardTextAsync`、`SetClipboardTextAsync`、`OpenFilesAsync`、`SaveFileAsync`、`StoreSecretAsync`、`LoadSecretAsync`、`DeleteSecretAsync`、`RegisterFontAsync`、`RequestNotificationPermission` 与 `RequestFullscreen`，原生目标在调用返回前完成，浏览器在事件循环上完成
- 浏览器（`GOOS=js GOARCH=wasm`）成为与原生并列的发布目标，`app.Run` 与 `app.RunCanvas` 运行同一棵组件树、同一套命中、焦点、输入与无障碍路径，由 Canvas2D 绘制
- 原生文件拖放带上可读的 `ui.FileDropEvent.Files`（`ui.FileDropFile`），浏览器拖放没有路径但可以读取文件内容；不适用的一体化能力返回 `ErrUnsupported` 等类型化错误，不伪造成功
- 新增 `app.ClipboardFiles` 与 `app.SetClipboardFiles`，文件管理器复制的文件列表可以在 macOS、Windows 与 Linux 之间读写

- 新增 `components.TextSelection`，一次指针拖动可以从一段文字开始、在另一段文字结束，并给出各段的选区与合并后的复制文本
- 新增 `headless.RecordOptions.ShowInput` 与 `inspector.Inspector`，录制帧可以显示按压环和按键提示，开发覆盖层可以列出悬停控件或全部控件

- 新增 `app.DirectoryWatch`、`app.WatchDirectory`、`app.WatchTree` 与 `app.ErrWatchTooLarge`，用 FSEvents、ReadDirectoryChangesW 与 inotify 报告目录或整棵树的变更，不轮询；打开的监视只保留一个阻塞 goroutine，名称会合并并有上限

- 新增 `Box.Draw`、`Box.DrawOver`、`flex.DrawContext`、`Box.Focused`、`Box.State`、`Box.Part` 与 `Box.Popup`，控件表面之外的绘制、任意焦点外观和自绘下拉都有公开入口；`SliderState.Fraction` 给出滑杆位置
- 新增导出的控件配方 `TextEntryRecipe`、`ButtonRecipe`、`CheckboxRecipe`、`PaintCheckboxMark`、`SwitchRecipe`、`SelectRecipe`、`TabTriggerRecipe`、`SegmentRecipe`、`PopupRecipe`、`DialogRecipe`、`PopoverRecipe` 与 `MenuItemRecipe`，应用自绘控件不必复制主题规则
- 新增 `PaintInputContent`、`PaintTextareaContent`、`InputSnapshot.Text`（`InputTextStyle`）、`InputSnapshot.Blink` 与 `SelectOptions.Unpainted`，自绘输入框可以复用同一套文本、光标、选区、组字与无障碍声明，也可以只声明不绘制

## 注意 · Caveats

浏览器目标是一个页面一个窗口：多窗口、状态栏图标、原生 web view、自定义 URL scheme 与目录选择不提供，同步剪贴板、文件对话框、密钥存储与字体注册会返回 `ErrAsyncRequired`、`ErrSecretStoreUnavailable` 或 `ErrUnsupported`，应按 `app.Supports` 分支并改用异步版本。窗口关闭在浏览器映射到 `beforeunload`，不能保证取消；需要保存的状态要在离开前写好。

以零值填充调用 `RoundedBorder` 的代码现在得到真正的描边；若之前依赖它顺带画出实心底，需要显式传入填充色。终端单元不再固定比例，列数会随字体度量变化；依赖固定 0.6em 的布局应改用 `Canvas.MonoCellSize`。

The browser target is one page and one window: multiple windows, status items, native web views, custom URL schemes and directory pickers are not provided, and synchronous clipboard, file-dialog, secret-store and font-registration calls return `ErrAsyncRequired`, `ErrSecretStoreUnavailable` or `ErrUnsupported`; branch on `app.Supports` and use the asynchronous form. Closing a browser window maps to `beforeunload` and cannot guarantee cancellation, so state that matters must be saved before the user leaves.

Code that calls `RoundedBorder` with a zero fill now gets a real outline; a caller that relied on it painting a solid interior must pass the fill explicitly. Terminal cells are no longer a fixed ratio and the column count changes with the font's metrics; layout that assumed 0.6em should use `Canvas.MonoCellSize`.
